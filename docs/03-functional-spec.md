# 3. 기능 명세 (Functional Specification)

[기능 정의](02-feature-definition.md)의 각 기능에 대해 입력·출력·처리 규칙·예외를 정의한다.
요구사항은 `F-XX-R#` 식별자로 관리한다.

---

## F-01 영상 업로드

### 동작
- 웹 UI에서 파일 선택 다이얼로그 또는 드래그앤드롭으로 영상 파일 1개를 업로드한다.
- 업로드는 청크 단위(권장 8MB)로 분할 전송하며, 네트워크 오류 시 실패한 청크부터 재개할 수 있다.

### 요구사항
| ID | 요구사항 |
|----|----------|
| F-01-R1 | 한 번에 파일 1개만 업로드할 수 있다 (멀티 클립은 v3+) |
| F-01-R2 | 업로드 진행률(%)을 실시간 표시한다 |
| F-01-R3 | 업로드 완료 시 잡(Job)이 생성되고 잡 ID가 발급된다 |
| F-01-R4 | 업로드 중 사용자가 취소할 수 있으며, 취소 시 서버의 부분 업로드 데이터는 삭제된다 |

### 예외 처리
| 상황 | 처리 |
|------|------|
| 파일이 영상이 아님 | 업로드 시작 전 확장자/MIME 1차 차단, 서버에서 2차 검증 후 `INVALID_MEDIA` 오류 |
| 용량 초과 | 업로드 시작 전 차단, 안내 메시지 표시 (제한값은 [8. 비기능 요구사항](08-non-functional.md) 참조) |
| 네트워크 단절 | 재개 가능 상태로 24시간 유지 후 만료 |

## F-02 입력 검증 및 정규화

### 동작
업로드된 파일을 검사하고 후속 파이프라인이 다루기 쉬운 형태로 변환한다.

### 처리 규칙
1. **컨테이너/코덱 검사**: ffprobe로 메타데이터 추출. 비디오 스트림이 없으면 거부.
2. **지원 입력 포맷**: MP4, MOV, WebM, MKV, AVI / 코덱 H.264, H.265, VP8, VP9, AV1.
3. **길이 검증**: 3초 미만 거부(`TOO_SHORT`), 상한 초과 거부(`TOO_LONG`, 기본 상한 10분).
4. **정규화(Transcode)**: 분석용 프록시 영상 생성 — H.264, 720p, 30fps, faststart. 원본은 그대로 보존하여 최종 렌더링에 사용.
5. **메타데이터 기록**: 해상도, 화면비, fps, 길이, 오디오 유무, 회전(rotation) 태그를 잡에 기록.

### 요구사항
| ID | 요구사항 |
|----|----------|
| F-02-R1 | 회전 메타데이터(스마트폰 세로 촬영)를 해석하여 실제 표시 방향 기준으로 처리한다 |
| F-02-R2 | 오디오 스트림이 없는 영상도 수용한다 (F-11은 건너뛰고 F-15 BGM을 기본 활성화) |
| F-02-R3 | 검증 실패 시 잡은 `FAILED` 상태가 되며 실패 사유 코드를 남긴다 |

## F-03 생성 옵션 지정

### 동작
업로드 시(또는 업로드 직후, 분석 시작 전) 생성 옵션을 지정한다. 모든 옵션은 선택 사항이며 미지정 시 자동 결정된다.

### 옵션 정의
| 옵션 | 값 | 기본값 |
|------|-----|--------|
| `targetDuration` | `15` / `30` / `60` / `90` (초) | `auto` (원본 길이에 따라 결정, §F-12) |
| `preset` | 프리셋 ID (예: `clean`, `bold`, `vlog`, `promo`) | `clean` |
| `subtitle` | `on` / `off` | `on` (음성 있을 때) |
| `bgm` | `auto` / `off` / BGM 트랙 ID | `auto` |
| `reframe` | `track` (피사체 추적 크롭) / `pad` (블러 패딩) / `auto` | `auto` |
| `language` | 자막 언어 힌트 (`ko`, `en`, `auto` …) | `auto` |

## F-10 장면 분석

### 동작
프록시 영상에서 시각적 세그먼트를 추출한다.

### 처리 규칙
1. **샷 경계 감지**: 히스토그램/콘텐츠 기반 장면 전환 감지(예: 콘텐츠 차이 임계값 방식). 결과는 샷 목록 `[start, end]`.
2. **피사체 감지**: 얼굴 감지를 샘플링 프레임(초당 2~5프레임)마다 수행, 샷별 주요 피사체의 궤적(트랙)을 산출한다. → F-13 리프레이밍의 입력.
3. **모션/품질 신호**: 샷별 평균 모션 크기, 흔들림, 노출(과암/과포화) 점수를 계산한다. → F-12 점수화의 입력.

### 출력 (세그먼트 레코드)
```json
{
  "type": "shot",
  "start": 12.40, "end": 18.92,
  "signals": { "motion": 0.61, "faces": 1, "quality": 0.82 },
  "subjectTrack": [{ "t": 12.40, "cx": 0.42, "cy": 0.37, "w": 0.18, "h": 0.30 }]
}
```
(좌표는 프레임 크기 대비 0~1 정규화 값)

## F-11 음성 분석 (STT)

### 처리 규칙
1. **음성 추출**: 프록시에서 오디오를 16kHz mono WAV로 추출.
2. **음성 인식**: Whisper 계열 모델로 전사. 단어 단위 타임스탬프 필수.
3. **발화 세그먼트화**: 문장/구 단위로 그룹화, 무음(≥ 0.8초) 경계 기록.
4. **언어 감지**: `language=auto`일 때 감지 결과를 잡에 기록.

### 요구사항
| ID | 요구사항 |
|----|----------|
| F-11-R1 | 단어별 `start`/`end` 타임스탬프를 보존한다 (자막 싱크의 기준) |
| F-11-R2 | 오디오가 없거나 발화가 감지되지 않으면 결과를 빈 목록으로 두고 후속 단계는 정상 진행한다 |
| F-11-R3 | 무음 구간 목록을 산출한다 (F-12에서 컷 포인트 후보로 사용) |

---

## F-12 하이라이트 추출 (자동 컷 편집)

### 목적
원본에서 목표 길이에 맞는 "가장 볼만한" 구간 조합을 선택한다.

### 처리 규칙
1. **목표 길이 결정** (`targetDuration=auto`인 경우):
   - 원본 ≤ 20초 → 원본 전체 사용 (컷 편집 생략, 리프레이밍만 수행)
   - 원본 ≤ 75초 → 60초
   - 원본 > 75초 → 60초 (v1에서 90초 옵션 노출)
2. **점수화**: 세그먼트별 점수 = 가중합(음성 밀도, 음량 에너지, 모션, 얼굴 존재, 화질) − 페널티(무음 위주, 흔들림, 과암).
   - 가중치는 설정값으로 외부화하며 기본값은 파이프라인 명세 §4.3에 정의.
3. **선택(Selection)**: 점수 상위 세그먼트를 시간 순서를 유지한 채 그리디로 채택하되,
   - 발화 세그먼트는 **문장 중간에서 자르지 않는다** (경계를 무음/문장 끝으로 스냅).
   - 인접 채택 세그먼트 간 간격 < 1.5초면 병합한다.
   - 총합이 목표 길이 ±10% 이내가 되도록 마지막 세그먼트를 트리밍한다.
4. **컷 전환**: 세그먼트 사이는 하드 컷 기본, 프리셋에 따라 0.2초 크로스페이드.

### 요구사항
| ID | 요구사항 |
|----|----------|
| F-12-R1 | 선택된 컷은 항상 원본 시간축 오름차순이다 (순서 재배열 금지) |
| F-12-R2 | 결과 길이는 목표 길이의 ±10% 이내여야 한다 (원본 전체 사용 시 제외) |
| F-12-R3 | 발화 도중 컷이 시작/종료되지 않도록 경계를 스냅한다 (허용 오차 0.15초) |
| F-12-R4 | 컷 결정은 컴포지션에 기록되어 사용자가 F-21에서 수정할 수 있다 |

## F-13 자동 리프레이밍 (9:16 변환)

### 처리 규칙
1. **모드 결정** (`reframe=auto`):
   - 원본이 이미 9:16(±5%) → 스케일만 수행.
   - 피사체 트랙(F-10)이 프레임의 60% 이상 시간 동안 존재 → `track` 모드.
   - 그 외 → `pad` 모드.
2. **`track` 모드 (피사체 추적 크롭)**:
   - 각 시점의 크롭 윈도우(9:16)를 피사체 중심에 배치.
   - 크롭 경로는 스무딩(저역 필터)하여 급격한 흔들림 방지. 샷 경계에서만 점프 허용.
   - 피사체가 사라진 구간은 마지막 위치 유지 → 3초 이상 지속 시 중앙 크롭으로 서서히 복귀.
3. **`pad` 모드 (블러 배경 패딩)**:
   - 원본을 9:16 캔버스 폭에 맞춰 축소 배치하고, 상하 여백은 원본 확대+가우시안 블러로 채운다.
4. 출력 캔버스는 1080×1920 고정.

### 요구사항
| ID | 요구사항 |
|----|----------|
| F-13-R1 | 크롭 윈도우가 원본 프레임 밖으로 나가지 않는다 |
| F-13-R2 | 크롭 경로의 프레임 간 이동량을 제한하여(최대 프레임 폭의 1.5%/frame) 멀미성 흔들림을 방지한다 |
| F-13-R3 | 자막 안전 영역(하단 25%)과 플랫폼 UI 영역(상단 10%, 우측 15%)을 고려해 피사체를 중앙~상단에 배치한다 |

## F-14 자동 자막

### 처리 규칙
1. F-11의 단어 타임스탬프를 기반으로 자막 블록을 만든다.
   - 한 블록 = 1~5단어(한국어는 8~14자), 표시 시간 0.5~3.0초.
   - 컷 편집(F-12) 후의 **출력 시간축으로 리매핑**하여 싱크를 맞춘다.
2. 스타일은 프리셋을 따른다: 폰트, 크기(기본: 화면 높이의 4.5%), 색, 외곽선/그림자, 강조(현재 단어 하이라이트) 여부.
3. 배치: 하단 안전 영역 위(화면 높이 65~78% 지점), 중앙 정렬, 최대 2줄.
4. 자막은 **렌더 시 번인(burn-in)** 하며, 원본 자막 데이터는 컴포지션에 보존한다(F-22 편집용).

### 요구사항
| ID | 요구사항 |
|----|----------|
| F-14-R1 | 자막 싱크 오차는 ±0.2초 이내여야 한다 |
| F-14-R2 | 컷에 포함되지 않은 발화의 자막은 출력되지 않는다 |
| F-14-R3 | 금칙어/욕설은 마스킹 옵션을 제공한다 (v1, 기본 off) |

## F-15 BGM 삽입

### 처리 규칙
1. **트랙 선택** (`bgm=auto`): 라이선스 확보된 내장 라이브러리에서 무드 태그(에너지, 템포) 기반 자동 선택. 무드 추정은 음성 밀도·모션 점수를 활용한 규칙 기반(초기).
2. **믹싱**: 원본 음성이 있으면 BGM은 -18dB 기준으로 덕킹(발화 구간 -24dB), 음성이 없으면 -8dB.
3. **길이 맞춤**: 출력 길이에 맞춰 페이드인 0.5초 / 페이드아웃 1.5초, 트랙이 짧으면 루프.

### 요구사항
| ID | 요구사항 |
|----|----------|
| F-15-R1 | BGM 트랙은 반드시 재배포 가능한 라이선스(자체 보유/CC0 등)만 사용한다 |
| F-15-R2 | 최종 오디오는 라우드니스 -14 LUFS(±1) 로 노멀라이즈한다 |

## F-16 템플릿/프리셋 적용

### 프리셋 구성 요소
| 요소 | 내용 |
|------|------|
| 자막 스타일 | 폰트, 크기, 색, 외곽선, 애니메이션 |
| 색 보정 | LUT 또는 밝기/대비/채도 프리셋 |
| 타이틀 카드 | 첫 1.5초 제목 오버레이 (제목은 STT 첫 문장 또는 사용자 입력) |
| 전환 효과 | 하드 컷 / 크로스페이드 |
| BGM 무드 | 프리셋별 기본 무드 태그 |

### 초기 제공 프리셋
`clean`(무장식 기본), `bold`(큰 자막+강조색), `vlog`(부드러운 색감+잔잔한 BGM), `promo`(타이틀 카드+템포 빠른 BGM)

## F-20 결과 미리보기

- 렌더링 완료 시 웹 플레이어에서 즉시 재생(스트리밍) 가능해야 한다.
- 미리보기 화질은 최종본과 동일 파일을 사용한다 (별도 저화질 생성은 최적화 항목).

## F-21 컷 범위 보정

- 원본 타임라인 위에 자동 선택된 하이라이트 구간을 시각화한다.
- 사용자는 구간 추가 / 삭제 / 시작·끝 드래그 조정이 가능하다.
- 조정 결과는 컴포지션에 반영되며, 자막 리매핑(F-14)이 자동 재계산된다.
- 총 길이가 플랫폼 상한(90초)을 넘으면 저장을 차단하고 경고한다.

## F-22 자막 편집

- 자막 블록 목록에서 텍스트 수정, 블록 삭제, 표시 시간 ±0.5초 조정이 가능하다.
- STT 원문은 보존하고 수정본을 별도 필드로 저장한다 (모델 품질 평가에 활용).

## F-23 스타일 변경

- 프리셋 전체 교체 또는 개별 요소(자막 스타일만, BGM만) 교체를 지원한다.

## F-24 재렌더링

- 보정 후 "다시 만들기" 실행 시 분석(F-10/F-11)은 재사용하고 컴포지션 → 렌더링만 재실행한다.
- 재렌더링은 잡의 새 **리비전**으로 기록되며 이전 결과물도 이력에 남는다 (최근 5개 보관).

## F-30 최종 렌더링 및 다운로드

- 출력 스펙: MP4 컨테이너, H.264 High Profile, 1080×1920, 30fps, 목표 비트레이트 8~10Mbps(VBR), AAC 128kbps 48kHz, `+faststart`.
- 다운로드는 서명된 URL(만료 24시간)로 제공하며 만료 후 재발급 가능하다.
- 결과물 보관 기한: 기본 7일 (F-41 이력 정책과 연동).

## F-40 잡 상태 조회 및 알림

- 잡 상태 머신: `UPLOADING → QUEUED → ANALYZING → COMPOSING → RENDERING → DONE | FAILED | CANCELED` ([7. 데이터 모델](07-data-model.md) 참조).
- 클라이언트는 폴링(기본 2초) 또는 SSE로 상태·진행률(%)·현재 단계를 받는다.
- 실패 시 사용자에게 노출할 사유 메시지와 내부 오류 코드를 구분해 기록한다.

## F-41 잡 이력 관리

- 세션(익명) 또는 계정 기준으로 잡 목록을 조회한다: 썸네일, 생성일, 길이, 상태.
- 보관 기한이 지난 결과물은 파일만 삭제하고 메타데이터는 유지한다(썸네일 포함).

## F-42 사용자 계정

- MVP는 익명 세션 쿠키 기반. v2에서 이메일/OAuth 로그인 도입, 익명 이력의 계정 병합을 지원한다.

## 3.1 대표 유스케이스

### UC-1: 완전 자동 생성 (해피 패스)
1. 사용자가 90초짜리 가로 영상을 업로드한다.
2. 시스템이 검증 후 분석을 시작하고, 진행률이 표시된다.
3. 60초 하이라이트 + 피사체 추적 9:16 크롭 + 자막 + BGM이 적용된 결과가 생성된다.
4. 사용자가 미리보기 확인 후 다운로드한다.

### UC-2: 자막 오탈자 수정
1. UC-1 완료 후 자막 한 블록의 오인식을 발견한다.
2. 자막 편집에서 텍스트를 수정하고 재렌더링한다.
3. 새 리비전이 생성되고 미리보기가 갱신된다.

### UC-3: 음성 없는 풍경 영상
1. 무음 영상 업로드 → STT 결과 없음.
2. 자막 없이 BGM이 기본 적용되고, 모션/화질 점수만으로 하이라이트가 선택된다.

### UC-4: 실패 및 복구
1. 지원하지 않는 파일(오디오만 있는 M4A) 업로드 시도.
2. 검증 단계에서 `INVALID_MEDIA`로 즉시 실패 처리, 사유가 안내된다.
