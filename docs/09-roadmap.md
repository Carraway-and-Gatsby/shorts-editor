# 9. 로드맵 (Roadmap)

[2.3 릴리스 단계별 범위](02-feature-definition.md#23-릴리스-단계별-범위)를 실행 가능한 마일스톤으로 구체화한다.
각 마일스톤은 **동작하는 수직 슬라이스**를 목표로 한다 (레이어별 완성이 아니라 끝에서 끝까지 이어지는 기능 단위).

## M0 — 프로젝트 골격

- [x] 모노레포 구조 셋업 (`apps/`, `workers/`, `packages/`) + Docker Compose
- [x] CI: 린트, 타입체크, 테스트 파이프라인
- [x] `packages/shared`: composition 스키마(JSON Schema + 타입), 잡 상태 상수
- [x] 큐/스토리지 추상화 인터페이스와 로컬 구현체 (`packages/queue`, `packages/storage`)

**완료 기준**: `docker compose up`으로 전 서비스가 뜨고 헬스체크가 통과한다.

## M1 — 파이프라인 뼈대 (변환만 하는 통짜 흐름)

- [x] 업로드 API (청크 업로드, 잡 생성) — F-01, F-02 일부
- [x] Ingest 워커: 검증 + 프록시 + 썸네일
- [x] Render 워커: **컷/자막 없이** 9:16 pad 모드 변환만 수행 — F-13 pad
- [x] 잡 상태 머신 + SSE 진행률 — F-40
- [x] 최소 웹 UI: 업로드 → 진행률 → 미리보기 → 다운로드 — F-20, F-30

**완료 기준**: 어떤 지원 포맷 영상이든 업로드하면 9:16 MP4가 나온다. (UC-1의 골격)

> M1 구현 노트: 하이라이트 선택(F-12)은 M2 범위이므로, M1의 기본 컴포지션은
> 원본 **시작부터 목표 길이(기본 60초)** 만큼을 단일 컷으로 사용한다.

## M2 — 자동 편집 두뇌 (MVP 완성)

- [x] Analyze 워커: 샷 감지 + 신호 점수 — F-10
- [x] Analyze 워커: STT + 무음 감지 — F-11
- [x] Compose: 하이라이트 선택 알고리즘 — F-12
- [x] 피사체 추적 크롭 (`track` 모드) — F-13 완성
- [x] 자막 생성·리매핑·번인 — F-14
- [x] 평가셋 구축: 튜닝 루프(`pnpm eval`) + 합성 케이스 3종 — 실제 라벨 영상 20개 확보는 계속 진행 ([eval/README.md](../eval/README.md))

**완료 기준**: [UC-1](03-functional-spec.md#31-대표-유스케이스)(완전 자동 생성)과 UC-3(무음 영상)이 통과한다. → **MVP(v0) 릴리스**

> M2 구현 노트:
> - 얼굴 감지는 오프라인 동작 가능한 OpenCV Haar cascade로 시작 (YuNet 등 상위 모델은 정확도 요구 시 교체).
> - STT는 faster-whisper(`[stt]` extra). 미설치·실패 시 자막 없이 진행하는 폴백이 명세대로 동작한다.

## M3 — 보정과 스타일 (v1)

- [x] 생성 옵션 UI — F-03
- [x] BGM 라이브러리 + 믹싱/라우드니스 — F-15
- [x] 프리셋 4종 (`clean`/`bold`/`vlog`/`promo`) — F-16
- [x] 컷 보정 타임라인 UI — F-21
- [x] 자막 편집 UI — F-22
- [x] 재렌더링(리비전) — F-24
- [x] 잡 이력 + 보관 정책 배치 — F-41

**완료 기준**: UC-2(자막 수정 → 재렌더)가 통과한다. → **v1 릴리스**

> M3 구현 노트:
> - BGM은 저장소에서 합성한 CC0 트랙 3종으로 시작 (assets/bgm/README.md). 믹싱은
>   사이드체인 덕킹(발화 중 감쇠) + 페이드 + -14 LUFS 노멀라이즈.
> - 프리셋은 자막 스타일 + BGM 무드 + 타이틀 카드(promo)로 구성. LUT/전환 효과는 후속.
> - 보정은 드래프트 방식: PATCH → 드래프트 저장, POST /render → 새 리비전 확정.
> - 보관 배치는 만료 잡의 파일 정리(썸네일 보존)와 리비전 5개 상한을 처리.
>   프록시/오디오 72시간 규칙은 후속 (docs/07-data-model.md §7.5).

## M4 — 계정과 확장 (v2)

- [x] 사용자 계정, 익명 이력 병합 — F-42
- [x] 스타일 개별 교체 — F-23
- [x] S3 스토리지 드라이버(Node/Python), 워커 스케일아웃 — CDN 서명 URL은 인프라 작업으로 후속
- [x] 금칙어 마스킹(F-14-R3), 클라우드 STT 옵션 재검토(ADR-6)

> M4 구현 노트:
> - 계정은 이메일+비밀번호(scrypt). 가입/로그인 시 현재 세션의 익명 잡이 계정으로 병합된다.
>   OAuth는 후속 (라우트 구조상 프로바이더 추가만 필요).
> - 스토리지는 `STORAGE_DRIVER=local|s3` 스위치. S3 드라이버는 Node(@aws-sdk)와
>   Python(boto3) 모두 구현, S3 호환 목 서버로 검증됨. 다운로드는 여전히 API 경유
>   서명 URL이며 CloudFront/CDN 직접 서빙은 배포 인프라 단계의 작업.
> - 스케일아웃: 워커 무상태 확인, `WORKER_CONCURRENCY` + `--scale` 지원.

## 리스크와 대응

| 리스크 | 영향 | 대응 |
|--------|------|------|
| 하이라이트 품질이 기대 이하 | 제품 핵심 가치 훼손 | M2에서 평가셋 기반 튜닝을 기능 구현과 동급 작업으로 취급. 자동 결과가 나빠도 F-21 보정으로 탈출구 확보 |
| 피사체 추적 크롭의 흔들림/오추적 | 시청 불가 수준의 결과물 | 스무딩 규칙(F-13-R2) + 신뢰도 낮으면 pad 모드 자동 폴백 |
| CPU 렌더링 처리 시간 초과 | NFR-10 미달 | 프록시 기반 병렬 처리, NVENC 지원, 워커 수평 확장 준비 |
| STT 오인식(한국어 고유명사 등) | 자막 품질 저하 | 자막 편집(F-22)으로 보완, stt_corrections 수집으로 개선 우선순위 판단 |
| BGM/폰트 라이선스 | 법적 리스크 | NFR-36/NFR-62: 등록 시 라이선스 검증 절차 필수화 |
